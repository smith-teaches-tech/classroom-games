Set it up

The screens below are mock-ups. Your screen may look a little different, but the names of the settings will match. Example values use a made-up app called Mood Tracker by the GitHub user yourname. Use your own.

1

Turn on email sign-in

Supabase

Your project → Authentication → Sign In / Providers → Email

  1. Check that the Email provider is on.
  2. Turn Confirm email off.
  3. Set Minimum password length to 8 or more.
  4. Pick a Password requirement, like letters and digits.
  5. Click Save.
Why turn off Confirm email? Supabase's free email sender only sends to people on your Supabase team, and only a few emails an hour. Your friends would never get the confirmation email, so they could never sign in. Real apps pay for their own email service. We're skipping it.
Think about it: with confirmation off, someone could sign up using an email address that isn't theirs. Is that a problem for your app?

2

Tell Supabase where your app lives

Supabase

Authentication → URL Configuration

  1. Set Site URL to your GitHub Pages address, for example https://yourname.github.io/mood-tracker/
  2. Under Redirect URLs, add the same address with ** on the end.
  3. Add http://127.0.0.1:5500/** so sign-in also works when you test with Live Server.
  4. Click Save.
Why? At the end of GitHub sign-in (step 7 in the diagram), Supabase has to send the person back to your app. It will only send people to addresses on this list. Skip this and sign-in dumps you on localhost:3000, a page that doesn't exist.

iPad: you don't use Live Server, so skip the 127.0.0.1 line. You'll test on your GitHub Pages site.

3

Copy Supabase's callback URL

Supabase

Authentication → Sign In / Providers → GitHub

  1. Click GitHub in the list to open its settings.
  2. Find Callback URL (for OAuth) and click Copy.
  3. Leave this tab open. You'll come back to it in Part 6.
What is it? It's Supabase's door, not your app's. When GitHub hands out the one-time ticket (step 4 in the diagram), it sends it to this address. It always ends in /auth/v1/callback.

4

Register your app with GitHub

GitHub

Your profile picture → Settings → Developer settings (bottom of the left menu) → OAuth Apps → New OAuth App

  1. Application name: your app's real name. People see it when they click Authorize.
  2. Homepage URL: your GitHub Pages address.
  3. Authorization callback URL: paste the Supabase callback URL from Part 3.
  4. Leave Enable Device Flow unticked.
  5. Click Register application.
Most common mistake: putting your GitHub Pages address in the callback box. The callback is the Supabase address ending in /auth/v1/callback. Get this wrong and GitHub says "redirect_uri is not associated with this application."

5

Get the Client ID and make a Client Secret

GitHub

You land on your new app's page automatically.

  1. Copy the Client ID. It's not secret. It's your app's name tag.
  2. Click Generate a new client secret. GitHub may ask for your password first. (Try it in the mock-up.)
  3. Copy the secret right away. GitHub shows it once. Leave the page and it's gone.
  4. Go straight to Part 6 and paste it into Supabase.
Where the secret must never go: config.js or any file in your repo, your AI chat, a Google Doc, a screenshot. Your AI never needs it. Only Supabase does.

6

Lock the secret in Supabase

Supabase

Back to your Supabase tab: Authentication → Sign In / Providers → GitHub

  1. Turn Enable Sign in with GitHub on.
  2. Paste the Client ID.
  3. Paste the Client Secret.
  4. Click Save.
This is the vault. The secret now lives on Supabase's servers. It never gets sent to anyone's browser. Look back at the diagram: the only arrows that carry it are the back-room ones (steps 5 and 6).

If your Client Secret leaks

It got pushed to GitHub, pasted into a chat, or ended up in a screenshot? Don't panic. It takes two minutes:

GitHub → your OAuth App → Delete the old secret → Generate a new client secret → paste it into Supabase (Part 6) → Save. The old one stops working the moment you delete it.

For your diagram

When you draw your app's data flow, show the GitHub sign-in. Mark which arrows pass through the browser, and draw a lock where the Client Secret lives. Then answer: your publishable key is public and that's fine. Why isn't the Client Secret?
