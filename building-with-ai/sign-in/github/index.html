Set Up Sign in with GitHub

Finish email sign-in first. This page adds a GitHub button to the sign-in screen you already have. You'll make a real secret today, so read the red boxes.

Where does the GitHub secret come from? You make it yourself, free, in your own GitHub account. You register your app with GitHub as an "OAuth App" (step 3), and GitHub gives you a Client ID and a Client Secret for it (step 4). Then you paste both into Supabase (step 5).

You'll bounce between two websites, so open Supabase in one tab and GitHub in another before you start. Each site needs something the other one makes.

1 Supabase→2 Supabase→3 GitHub→4 GitHub→5 Supabase→6 Your AI→7 Test

The screens below are mock-ups. Your screen may look a little different, but the names of the settings will match. Example values use a made-up app called Mood Tracker by the GitHub user yourname. Use your own.

1

Tell Supabase where your app lives

Supabase

Your project → Authentication → URL Configuration

  1. Set Site URL to your GitHub Pages address, for example https://yourname.github.io/mood-tracker/
  2. Under Redirect URLs, add the same address with ** on the end.
  3. Add http://127.0.0.1:5500/** so sign-in also works when you test with Live Server.
  4. Click Save.
Why? At the end of GitHub sign-in (step 10 in the diagram), Supabase has to send the person back to your app. It will only send people to addresses on this list. Skip this and sign-in dumps you on localhost:3000, a page that doesn't exist.

iPad: you don't use Live Server, so skip the 127.0.0.1 line. You'll test on your GitHub Pages site.

2

Copy Supabase's callback URL

Supabase

Authentication → Sign In / Providers → GitHub

  1. Click GitHub in the list to open its settings.
  2. Find Callback URL (for OAuth) and click Copy.
  3. Leave this tab open. You'll come back to it in step 5.
What is it? It's Supabase's door, not your app's. When GitHub hands out the one-time ticket (step 7 in the diagram), it sends it to this address. It always ends in /auth/v1/callback.

3

Register your app with GitHub

GitHub

Your profile picture (top right) → Settings → Developer settings (bottom of the left menu) → OAuth Apps → New OAuth App

Shortcut: github.com/settings/applications/new

If you've never made one before, the button says Register a new application instead of New OAuth App. Same thing.

  1. Application name: your app's real name. People see it when they click Authorize.
  2. Homepage URL: your GitHub Pages address.
  3. Authorization callback URL: paste the Supabase callback URL from step 2.
  4. Leave Enable Device Flow unticked.
  5. Click Register application.
One OAuth App per app. An OAuth App can only have one callback URL, and each Supabase project has its own callback URL. If you have two apps on two Supabase projects, make two OAuth Apps.
Most common mistake: putting your GitHub Pages address in the callback box. The callback is the Supabase address ending in /auth/v1/callback. Get this wrong and GitHub says "redirect_uri is not associated with this application."

4

Get the Client ID and make the Client Secret

GitHub

You land on your new app's page automatically. This is step 1 of the diagram: GitHub makes the secret.

  1. Copy the Client ID. It's not secret. It's your app's name tag.
  2. Click Generate a new client secret. GitHub may ask for your password first. (Try it in the mock-up.)
  3. Copy the secret right away. GitHub shows it once. Leave the page and it's gone.
  4. Go straight to step 5 and paste it into Supabase. Nowhere else.
Left the page before copying it? It's not gone for good. Go back to your app's page (Settings → Developer settings → OAuth Apps → your app), click Generate a new client secret again, and use the new one. Delete the old one you never copied.
Where the secret must never go: config.js or any file in your repo, your AI chat, a Google Doc, a screenshot. If it ends up in your code, anyone can pretend to be your app, and deleting the line doesn't undo it. Why.

5

Lock the secret in Supabase

Supabase

Back to your Supabase tab: Authentication → Sign In / Providers → GitHub. This is steps 2 and 3 of the diagram.

  1. Turn Enable Sign in with GitHub on.
  2. Paste the Client ID.
  3. Paste the Client Secret.
  4. Click Save.
  5. Clear your clipboard: copy any other word, so the secret isn't sitting there waiting to be pasted somewhere by accident.
This is the vault. The secret now lives on Supabase's servers. It never gets sent to anyone's browser. Your app will never need it.

6

Ask your AI for the GitHub button

Your AI

Upload your current index.html, app.js and config.js (the versions with email sign-in working), then paste this prompt.

If your AI asks for the Client Secret, say no. If the code it gives you has a line like clientSecret: or secret:, don't use it. Ask it to redo the code without one.
When the code comes back, check: you should see signInWithOAuth with provider: 'github', and nothing else about GitHub except the button.
Prompt

Use supabase.auth.signInWithOAuth with provider 'github'. 2. Set redirectTo to window.location.origin + window.location.pathname so it works on Live Server and on GitHub Pages. 3. When someone comes back from GitHub, they should see my app, signed in, the same way as with email. Show their GitHub username or email. 4. If something goes wrong, show the error on the page. Do not put any secret keys in my code. The GitHub Client Secret is already saved in my Supabase dashboard, so you will never need it. Change nothing else. Tell me exactly which file each change goes in.

If your Client Secret leaks

It got pushed to GitHub, pasted into a chat, or ended up in a screenshot? Tell your teacher, then fix it right away. Deleting it from your code is not enough, because your repo's history keeps old versions.

  1. GitHub → your profile picture → Settings → Developer settings → OAuth Apps → your app.
  2. Under Client secrets, Delete the leaked secret. It stops working right away.
  3. Click Generate a new client secret and copy it.
  4. Supabase → Authentication → Sign In / Providers → GitHub → paste the new secret → Save.
  5. Remove the old secret from your code anyway, and push.
