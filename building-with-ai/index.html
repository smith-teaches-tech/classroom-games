How to Keep Working on a Project

Building with AI — your folder, your project file, and the loop you'll use all year

The chat is temporary. Your folder is the project.
Read this first. There's a lot of saving and downloading in here. That's on purpose — you're doing by hand what real coding software does automatically. Later this year we'll switch to tools that handle it for you. For now, doing it manually is how you'll actually understand what those tools are doing. This is how you pick up an old project and keep building on it with a fresh, clean chat.

1Make your folder — name it after your game

One folder per project. Name it what the game is called, in lowercase with dashes. Future you will thank present you.

First, turn on file extensions. Your computer hides the end of file names, and that causes a genuinely annoying problem about three minutes from now. Fix it before you do anything else.

  1. Open Finder
  2. Finder → Settings (or ⌘ ,) → Advanced
  3. Tick "Show all filename extensions"
  4. Desktop → right-click → New Folder
  1. Open File Explorer
  2. Windows 11: View → Show → tick File name extensions
    Windows 10: the View tab → tick File name extensions
  3. Desktop → right-click → New → Folder
  1. Chromebooks already show extensions — nothing to change
  2. Files app → My files → right-click → New folder

Now name it. Your game is called Escape the Science Lab? The folder is escape-the-science-lab. All lowercase, dashes instead of spaces, no capitals, no apostrophes.

Put it on your Desktop. Not Downloads — things go there to die.

Why lowercase-with-dashes? Later this year your project goes on the real internet, and web addresses hate spaces and capital letters. Naming it properly now means you won't have to rename everything later.

2Describe your game — and let AI write the project file

You don't have to write Markdown by hand. You describe the game; Gemini writes the file.

Open a chat and describe your game idea in normal language. Then paste this:

I'm building a browser game and I need a project file for it.

Ask me any questions you need to understand my idea properly.
Then write me a project file in Markdown that includes:

- What it is (one sentence)
- Who it's for
- How you play
- Each level: the puzzle, and how you win it
- Look and feel
- Rules it must ALWAYS follow
- What I'm NOT doing on purpose (things I'm leaving out of v1)
- Where we are right now (nothing built yet)
- A change log

Give it to me in ONE code block so I can copy the whole thing.
Answer its questions properly. This is the one moment where being lazy costs you the most. Every question it asks is a decision you'd otherwise have to make later, in a worse mood, with a half-broken game.

3Get that file into your folder

Copy the Markdown it gave you, then use the tool below to save it correctly.

Click the copy button on the code block Gemini gave you (or select it all and copy). Then paste it here:

💾 Save your project file

Paste the Markdown below and download it as a properly-named file. Then move it from Downloads into your game folder.

Why this tool exists: if you try to make a .md file by hand in TextEdit or Notepad, they'll quietly save it as project.md.txt or project.rtf and nothing will work properly. This button gets the name right every time.

4Look at your file

Always open a file after you save it. Always.

Drag the file into a Chrome tab. It opens instantly, on any computer, and shows you exactly what's in it.

Right-click → Open With → TextEdit. If you edit and save from TextEdit, do Format → Make Plain Text first.

Right-click → Open With → Notepad. Windows 11 Notepad understands Markdown and can show it formatted or raw — look for the formatting toggle.

Double-click it — it opens in the built-in Text app.

What am I even looking at? Markdown is just text with a few symbols. # means heading, **bold** means bold, - means a list item. That's basically all of it.

Open it in a text editor and it looks ugly. Paste it into Gemini and it looks beautiful. The file didn't change — the reader changed. That's why this format never breaks: there's nothing in it to break.

Check the name. In your folder it must say exactly project.md — not project.md.txt, not project (1).md, not project.rtf. Rename it if it's wrong. This single thing breaks more projects than anything else.

5Open a NEW chat and build it

Not the chat where you designed it. A brand new one. This is the whole point.

Start a fresh chat. Attach or paste your project.md, then send this:

Here is the project file for a game I'm building. Read it, then
tell me in your own words what this game is and what Level 1
needs to do — and wait. Don't build anything yet.

Read what it says back. Is that actually your game? If it got something wrong, your file is wrong — go fix the file, not the chat. That's the test. That's why the "and wait" is in there.

Once it's got it right:

Now build Level 1 only, as ONE self-contained HTML file.
Structure the code so more levels can be added later.
Keep it simple.

6Save the game into your folder and test it

Copy all the code — and I mean all of it.

Click inside the code block, press Ctrl+A / ⌘A, and copy. Then:

💾 Save your game file

Paste the HTML below and download it. Then move it into your game folder, next to project.md.

Now double-click index.html. Your game opens in the browser.

Look at the address bar. It says file:/// — not https://. Turn off your wifi; it still works. This game lives on your computer and nobody else on Earth can open it. That's the difference between a file and a website, and we'll cross that gap later.

Test it properly

  • Play it start to finish
  • Click the wrong things on purpose
  • Click the same thing twice, fast
  • Shrink the window until it's phone-shaped
  • Replay the levels you already finished — new code breaks old levels all the time

7Update your project file, then close the chat

This is the step everyone skips and the one that saves you. Never close a chat without it.

Ask the chat you're in:

Update my project file to match what we just built. Fill in
"Where we are right now" — what's working, what's broken, and
what I want to add next. Add a change log line. Give me the
whole updated file in ONE code block.

Then scroll back up to the project file saver in step 3, paste the updated version, download it, and replace the old project.md in your folder. Same for the game file if it changed — the new index.html replaces the old one.

The test that matters: if you lost this chat right now and had to finish the game tomorrow with nothing but your folder — could you? If not, your file isn't finished.

8Next level? New chat.

Every level gets a fresh chat. By the third time this takes you about two minutes.

1
Open a brand new chat
2
Give it project.md — what the game is supposed to be
3
Give it index.html — what the game currently is
4
Use the handoff prompt below and make it prove it understood
5
Ask for the next level
6
Test — new level and old ones
7
Update the file, save everything, close the chat

The handoff prompt — start every new chat with this

I'm continuing a project in a new chat. Here is my project file
and my current code. Read both, then tell me in your own words
what this game does and where I left off — and wait. Don't change
anything yet.

Then, once it's played your project back correctly

Now add Level 2 exactly as described in the project file.
Change nothing else. Keep it one self-contained HTML file.

"Change nothing else" is doing a lot of work. Leave it out and AI will cheerfully rewrite your whole game and break the parts you liked.

9Your folder should look like this

📁 escape-the-science-lab/
   📄 project.md   ← what the game is SUPPOSED to be. You decide this.
   📄 index.html  ← what the game currently IS. AI writes this.
   📄 index-level1.html  ← backups, so you can go back
   📄 index-level2.html

Two different kinds of thing, and the difference is the whole idea. project.md is your intent — where you're going. index.html is the current reality — where you are. A new chat needs both: one to know the destination, one to know the starting point.

10When something goes wrong

What you're seeingWhat to do
Blank white page You didn't copy all the code. Click inside the code block, Ctrl+A/⌘A, copy, paste again. This is the most common problem by far.
Double-clicking index.html opens a text editor Right-click → Open With → Chrome.
My file is called project.md.txt Turn on file extensions (step 1) and rename it. Or just re-download it using the saver in step 3.
It downloaded as index (1).html You already had one in Downloads. Rename it to index.html when you move it into your folder.
Level 2 broke Level 1 Normal — it's called a regression. Open your backup, or tell the AI exactly what broke. This is why you retest old levels.
The new chat has no idea what my game is Your project.md is too thin. That's not failure — it's showing you exactly what you forgot to write down. Fix the file.
The AI rewrote my whole game Add "Change nothing else" to every request. Then go back to your backup.

The debugging protocol

  1. Say what you expected, then what actually happened.
  2. Paste the whole error — not "there's an error," not half a screenshot.
  3. Ask it to explain the problem before fixing it. Read the explanation. If you don't follow it, ask again simpler.
  4. One fix at a time. Test after each one.

Step 3 is the one everybody skips, and it's the one that makes you good at this. Let AI fix things you don't understand and you end up with a game you can't explain — and explaining it is the actual assignment.
