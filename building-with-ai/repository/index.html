Your Repository

Building with AI — one place that holds every project you make

This repository does two jobs at once. It's where your teacher reads your code, and it's the website where the world clicks your links. Same folder, two audiences.
You set this up once. Every project after this one is just Part 4 and Part 5 again — a new folder, a new link. You will never rebuild this page, so it's worth getting right the first time.

Two ideas before you start

Every folder needs a file called index.html. You never type a filename into a web address — so how does a website know what to show you? One rule: it looks for index.html and shows that. Every folder on the web works this way. It's the front door, and that's the handle.

Your folders become your web addresses. That's the whole trick behind every website you've ever visited. Make a folder, you just made an address:

📁 yourusername.github.io/
   📄 README.md   ← who you are. For people reading your CODE.
   📄 index.html   ← your homepage. For people visiting your SITE.
   📁 haunted-library/
      📄 index.html   ← one project
   📁 quiz-master/
      📄 index.html   ← the next one

Which gives you these addresses, for free, without doing anything else:

yourusername.github.io/
yourusername.github.io/haunted-library/
yourusername.github.io/quiz-master/
Web addresses are case-sensitive. Your computer isn't. Haunted-Library and haunted-library are the same folder on your laptop and two completely different addresses on the internet. Your link works for you and breaks for everyone else. Lowercase everything, always — same rule as your project folders, same reason.

PART 1Your account

github.com — the site that will host everything you make.

ObjectiveAn account that still belongs to you after you leave this school.

Go to github.com and click Sign up. Use your school email.

Your username becomes your web address — permanently. Take a minute on this. It's the one decision here you can't undo.

Good: maya-builds   river-makes-things   kx-projects
Bad: your full name, your birth year, anything you'd be embarrassed by at nineteen.

Then add your personal email — do this now

Your school email will stop working one day. Your account shouldn't die with it.

your profile picture▸ Settings▸ sidebar: Access▸ Emails

Type your personal address into Add email address, click Add, then open that inbox and click the verification link.

One account, several emails. When your school address stops working, you make the personal one primary and remove the school one. Your username, your repository, and everything in it stay exactly the same. Nothing to move.

If GitHub asks you to set up two-factor authentication and you're in the middle of class, choose remind me later — but you will have to do it, and when you do, save the recovery codes somewhere personal. Save them to a school account and you can lose your GitHub account along with it.

PART 2Your repository

One repository for everything — not one per project.

DescriptionAnything. My projects works.
Public / PrivatePublic. Required — your site can't go live otherwise.
Add a README fileTick this box.

Click Create repository.

The name has to be exact. Username maya-builds means the repository is maya-builds.github.io — not Maya-Builds.github.io, not maya-builds.github.com. That precise name is what gives you a clean address instead of an ugly one. Get it wrong and nothing after this works.
Public means genuinely public. Anyone can read this and Google will find it. First name only — no last name, no school name, no city, no email or phone number, no photos of you or anyone else.

And deleting something later doesn't erase it. Every version you save is kept forever. That's the entire point of this tool, and it cuts both ways.

Write your README

The README is the first thing anyone sees when they look at your code — including your teacher. Click README.md, then the pencil icon, and replace what's there.

# Hi, I'm [first name]

This is where everything I build lives.

## What I'm into
-
-

## What I'm working on right now

Then click Commit changes… — a box pops up. Type a short message saying what you did, and click Commit changes to confirm.

A commit is a save with a note attached. That message box isn't decoration — every save is kept forever with your note on it. It's the change log from your project file, except this one keeps itself.

PART 3Turn the website on

Right now you have a repository. Two clicks make it a website.

ObjectiveA live web address that anyone can open and that never expires.
Settings▸ sidebar: Code and automation▸ Pages

Under Build and deployment:

  1. Set Source to Deploy from a branch
  2. The branch dropdown says None — change it to main
  3. Leave the folder dropdown on / (root)
  4. Click Save

Now wait one to three minutes and refresh the page. A green banner appears with your address. That's your website. It's live, right now, to the entire internet.

Open it on your phone. Not connected to your laptop, not on the school wifi — just your phone, anywhere. That address belongs to you now and it doesn't expire in an hour.

PART 4Add a project

One folder per project. You'll do this part again for everything you build.

ObjectiveOne of your projects living in its own folder, at its own web address.

First, name the folder

Name it after your project. The name is yours — the format isn't, because it lands in a web address:

  • all lowercase
  • dashes, never spaces
  • letters, numbers and dashes only — GitHub won't even let you type anything else here
  • short, because people have to type it

Now make it

Add file ▾▸ Create new file

In the filename box, type your folder name, then a slash, then index.html:

your-folder-name/index.html
Watch what happens when you type the /. GitHub builds the folder right in front of you. That slash is how folders get made here — there is no "new folder" button. Now you know.

Then paste your project in

Open your project's index.html, click inside it, press Ctrl+A / ⌘A to select all of it, copy, and paste into the big box.

Copying out of the Files app is fiddly. Easier: make the folder first with a placeholder, then use Add file ▾ → Upload files and pick your file straight from Files.

Also worth knowing — once this is live, you'll be able to run your own project on your own iPad for the first time. An iPad can't open an HTML file directly, so until now you've only ever seen it on someone else's screen.

Click Commit changes…, type a message like Add my project, and confirm.

Blank page when you visit it? You copied only part of the file. It's the most common bug there is. Click inside the code, Ctrl+A / ⌘A, copy again. Every time.
index.html is not optional. The folder name is yours to choose. The file inside it has to be called exactly index.html, or your address opens a page of raw code instead of your project.

PART 5Your homepage

The front page that links to everything. This is what you actually share with people.

ObjectiveA homepage at your main address, with a working link to each project.
Add file ▾▸ Create new file▸ filename: index.html

No slash this time. This one sits at the top level, next to your project folders.

Here's a starter that already works. Copy it, paste it in, and change the highlighted parts.

<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Maya — Projects</title>
<style>
  body { font-family: system-ui, sans-serif; max-width: 640px;
         margin: 0 auto; padding: 2.5rem 1.25rem; line-height: 1.6;
         background: #14141a; color: #e8e8ee; }
  h1 { font-size: 2.25rem; margin-bottom: .25rem; }
  .tag { color: #9a9aa8; margin-top: 0; }
  .card { display: block; padding: 1.25rem; margin-top: 1.5rem;
          border: 1px solid #33333f; border-radius: 12px;
          text-decoration: none; color: inherit; }
  .card:hover { border-color: #7c6cff; background: #1c1c26; }
  .card h2 { margin: 0 0 .35rem; font-size: 1.2rem; }
  .card p { margin: 0; color: #9a9aa8; }
</style>
</head>
<body>

  <h1>Maya</h1>
  <p class="tag">Things I'm building.</p>

  <a class="card" href="haunted-library/">
    <h2>Haunted Library</h2>
    <p>A three-room escape game.</p>
  </a>

</body>
</html>

Four things to change: the name in the title, the heading, and the link, name and description in that <a class="card"> block.

The link is the part that breaks. It has to be your folder name and a slash — haunted-library/ — and nothing else. Not https://..., no capital letters.

That's a relative link: it means "the folder sitting right next to this file." Which is why it keeps working no matter what your address is, or where the site moves to.

Commit it. Wait a minute or two, then reload your address.

PART 6Check it like a stranger

It working on your screen is not evidence. Other people's screens are.

ObjectiveProof that your site works for someone who isn't you, on a device that isn't yours.

Open your address in a new tab — the real address, not GitHub's preview.

Changes take a minute or two to appear. If you just committed something and don't see it yet, wait, then hard-refresh: Ctrl+Shift+R / ⌘⇧R.

PART 7Every project after this one

Come back to this page whenever you finish something new.

ObjectiveAdd any new project to your site in about five minutes, without setting anything up again.

Parts 1 to 3 were one-time setup. You never do them again. Adding your next project is just this:

1
Pick a folder name — lowercase, dashes, short
2
Add file ▾ → Create new file, filename new-folder/index.html
3
Paste the whole project in. Commit.
4
Open your top-level index.html and copy the existing <a class="card"> block
5
Paste it underneath, change the link, title and description. Commit.
6
Reload your site and click the new link
That's the payoff for setting it up properly. Your site grows by one folder and one link at a time. By the end of the year, one address shows everything you've made — and you'll never have rebuilt any of it.

FIXESWhen something goes wrong

Find what you're seeing, then read across.

What you're seeingWhat to do
404 on my main address The repository name isn't exactly username.github.io. Check it letter by letter in Settings.
404, and the name is right Pages isn't switched on, or it's pointing at the wrong branch. Settings → Pages → main → / (root) → Save.
Homepage works, project link 404s Capital letters. The folder name and the link have to match exactly, all lowercase. This is the most common problem on this page.
Project link 404s, no capitals A space in the folder name turned into %20. Rename the folder with dashes.
The link shows code, not my project The file inside the folder isn't called index.html. Rename it.
My project loads as a blank page You pasted only part of the file. Click inside the code, Ctrl+A / ⌘A, copy, paste again.
Nothing loads and I just turned Pages on The first build is the slow one. Wait three minutes, then hard-refresh.
My edit isn't showing up The site rebuilds on a delay. Wait two minutes, then Ctrl+Shift+R / ⌘⇧R.
The verification email never arrived Check spam. If it's not there, your school's mail filter blocked it — tell your teacher.
README shows raw # symbols The file isn't named README.md. Rename it.
