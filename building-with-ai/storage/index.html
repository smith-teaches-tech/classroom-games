Part 1

Where files live

Files are too big for a database table. Supabase keeps them in Storage, inside a bucket, like a shared drive for your app. Each person gets their own folder, named after their account ID.

Bucket: user-files
Maya's foldersunset.jpgvoice-memo.m4a
Sam's folderessay.pdf
ALLOWEDMaya uploads into her own folder.
BLOCKEDMaya tries to upload into, or delete from, Sam's folder.

The rules that decide this are called policies. They're the same idea as the rules on your tables: you can only touch your own stuff.

Part 2

Set your limits in two places

Your allowed file types and your size limit each go in two places. They do different jobs.

Place 1 · your app's codeHelps

Greys out the wrong file types in the file picker, and says "too big" or "wrong type" straight away.

But anyone can get around it. It runs in the browser, and people control their own browser.

Place 2 · your Supabase bucketBlocks

Refuses any file that's the wrong type or too big, even if someone skips your app completely.

This is the one that actually stops a file. It runs on Supabase, not in the browser.

Keep both lists the same. Add or remove a file type in one place, change it in the other.

Part 3

What to let in, and how big

Supabase doesn't scan files for viruses. So you choose what your bucket accepts.

Allow

  • Photos · JPG, PNG, WEBP, GIF
  • Video · MP4, MOV
  • Audio · MP3, M4A, WAV
  • Documents · PDF, Word (.docx)

Never allow

  • .html · a web page that runs its own code
  • .svg · looks like a picture, can hide code
  • .exe · a program
  • .zip · a sealed box, could hide anything
  • .docm · a Word file with macros (little programs)
10 MBOur limit for one file
1 GBAll your files together, on a free account
~10 secof phone video fits in 10 MB. Photos fit easily.

Part 5

View or download?

It depends on your app. But you should know what changes when a file is downloaded.

View on the pageStart here

Photos, video, audio and PDF show right on your page. The file stays inside the browser, which is built to keep it from doing harm.

Download buttonOnly if needed

The file is saved to the computer and opened by the computer's own apps. Add this only when people really need the file itself.

The risks of downloading

  • The browser stops protecting you. A disguised file, like the fake cat in Part 3, can only show up broken on a page. Downloaded, it gets opened by the computer, where it could run.
  • You can't take it back. Delete a photo from your app, and every downloaded copy still exists. Think about this for photos of people.
  • Word files always download. A browser can't show a .docx on the page. If people share documents with each other, ask for PDF instead.

Your own files: downloading is fine. Other people's files: view on the page, unless your app really needs a download.

Now build it

Write these five answers in your project file first:

  1. Which file types your app needs.
  2. Who can see the files.
  3. Your size limit (10 MB, unless your app is about video).
  4. Your bucket's name, like user-files.
  5. View only, or view and download, and for whose files.
